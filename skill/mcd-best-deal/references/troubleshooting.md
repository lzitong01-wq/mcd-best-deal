# 排障手册

本手册是 `SKILL.md` 排障速查的详细版，按「症状 → 原因 → 处理」组织。
命令中的 `<skill目录>` 指本技能所在目录（如 `~/.workbuddy/skills/mcd-best-deal`）。

## 一、Token 与连接

### 1.1 脚本报「未找到 Token」
**原因**：三级来源都不可用（优先级：环境变量 `MCD_MCP_TOKEN` > 通用凭证文件 `~/.mcd-best-deal/token` > `~/.workbuddy/mcp.json`）。
**处理**：
1. 运行 `node "<skill目录>/scripts/setup-connector.mjs"` 按提示粘贴 Token（推荐，所有平台通用）；
2. 或临时设置：`MCD_MCP_TOKEN=<Token> node <脚本> ...`；
3. 或手工写入通用凭证文件（一行一个 Token，`#` 开头为注释）。

### 1.2 HTTP 401 / 403
**原因**：Token 无效、过期或权限不足。
**处理**：到 https://open.mcd.cn/mcp/doc 重新申请 → 重跑 `setup-connector.mjs` 覆盖。不要反复重试同一 Token。

### 1.3 HTTP 429
**原因**：触发官方限流（每 Token 每分钟 600 次请求）。
**处理**：等待约 1 分钟后重试。本技能脚本为串行调用，正常流程不会触发。

### 1.4 平台工具不出现（连接器已配置但 AI 调不到工具）
**处理**（按平台）：
- WorkBuddy：连接器管理页对 `mcd-mcp` 点「Trust」→ 左下角「+」启用 → **重开一轮会话**；
- Claude Code：重启会话，输入 `/mcp` 确认 `mcd-mcp` 已加载；
- Codex：重启后运行 `codex mcp list` 确认；
- Trae：设置 → MCP 确认已添加并启用 → 重启。
**兜底**：技能脚本自带零依赖直连客户端，**不依赖平台工具加载**——工具没出现时，仍可用脚本完成全流程。

## 二、门店与时间

### 2.1 试算报「门店暂停营业」
**原因**：门店当前不在营业时间内，算价被拒。
**处理**：
1. 换营业中的门店（`collect.mjs` 已按「营业中优先」排序候选门店，可增大 `--max-stores`）；
2. 或改用**预约单**（带 `reservationDate` 计算，价格不受当前打烊影响）；
3. 或换时段再算。

### 2.2 门店搜索为空
**原因**：官方按「城市 + 关键词」区域搜索，关键词过窄或城市名不匹配。
**处理**：换更常见的商圈/地标（如「三里屯」「国贸」「五道口」），确认城市名。

### 2.3 价格与印象中/白天菜单不一样
**说明**：正常。价格随门店、时段（含宵夜时段）实时变化。本技能一切以**实时试算**为准，展示结果时须说明数据查询时间与范围。

## 三、优惠券

### 3.1 试算报「暂不支持多张券使用」（code 600022）
**原因**：官方硬限制——**一单只能一张券**。
**处理**：用拆单方案（引擎已自动生成：多张券分多单各用一张，总价为各单之和），或只保留最优一张。展示拆单方案时必须写明「需分 N 次下单、分别支付与取餐」。

### 3.2 试算报「促销规则不支持该商品」
**原因**：券与商品不匹配。带券商品的编码必须使用**券自己的** `products[].productCode`，而不是门店菜单里的编码。
**处理**：引擎已按此规则实现；手工试算时以券数据的 productCode 为准。

### 3.3 某门店券列表为空 / 券不可用
**原因**：券与门店、时段强绑定——不同门店可用券不同；门店打烊后券列表会变空。
**处理**：逐店、逐时段**实时查询**（不要缓存复用）；也可以先 `auto-bind-coupons` 领取「麦麦省」可领券，再查券包。

### 3.4 「可领取」的券不能直接用于算价
**原因**：可领券（`available-coupons`）只返回名称与状态，没有券码。
**处理**：先 `auto-bind-coupons` 领取，获得 couponId/couponCode 后才能用于试算。

## 四、算价与方案

### 4.1 全部候选试算失败
**处理**：查看 `plan.mjs` 输出 JSON 中 `failed` 列表的首条原因（通常是门店打烊或商品不可售）；换门店/时段重跑采集后再计算。

### 4.2 营养数据大量「不完整（不计分）」
**说明**：官方营养表与门店商品名为两套体系，仅**精确匹配**才计入营养分；模糊匹配会低估营养，故如实标注「不计分」。在 `plan.mjs` 输出的 `nutrition.details` 中可看到每个商品的匹配质量（exact / fuzzy / none）。不要用模糊数据冒充完整数据。

### 4.3 想调整推荐偏好
**处理**：编辑 `<skill目录>/config/rules.json`（模式权重、营养目标区间、距离上限、试算上限），或按用户口述修改后重跑 `plan.mjs`。这是本技能「细则透明可调」的入口。

## 五、网络与环境

### 5.1 连接 mcp.mcd.cn 超时
**处理**：先确认网络可达（`curl -sS https://mcp.mcd.cn` 有响应）；公司代理/防火墙环境需放行 `mcp.mcd.cn`；偶发超时重试一次即可。

### 5.2 Node 版本
**要求**：Node.js ≥ 20（ESM + fetch）。`node --version` 检查；版本过低时安装新版 Node 后重试。
