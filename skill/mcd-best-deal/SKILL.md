# 麦麦最优方案（mcd-best-deal）

回答「今天怎么吃麦当劳最合适」：想吃什么 + 几个人 + 预算 + 位置 → 输出一份**可验证**的方案排行。

> 本技能遵循 Agent Skills 开放标准，支持 WorkBuddy / Claude Code / Codex / Trae 等平台（各平台安装方式见仓库 README）。技能自带零依赖直连客户端，**不依赖特定平台的 MCP 加载**——只需 Token 可用即可工作。

**核心原则**：候选方案由脚本枚举，价格一律由官方算价器 `calculate-price` 实时试算，模型只负责理解需求、组织展示与守卫确认门控。**涉及麦当劳价格/优惠时必须走本技能流程——不要凭记忆或搜索给用户报价格。**

## 红线（必须遵守）

1. **价格只认官方试算**：任何「多少钱」都必须来自 `calculate-price` 的实时返回；不允许估算、拼凑、复用历史价格或自行加减优惠。
2. **一单一券**：官方硬限制「一单只能一张券」（实测报错码 600022）。多张券只能拆单；拆单方案必须明确标注「需分 N 次下单、分别支付与取餐」。
3. **不自动下单**：默认只算账与展示。只有用户明确要求下单，且门店、商品、数量、费用逐项确认后，才可调用 `create-order`；**支付永远由用户在官方流程完成**（把支付链接原样交给用户）。
4. **Token 安全**：不得在回复、示例、记忆、日志或任何文件中回显 Token；脚本只从环境变量 `MCD_MCP_TOKEN`、通用凭证文件 `~/.mcd-best-deal/token` 或本机平台配置读取。
5. **数据诚实**：查不到就说查不到，并说明已查范围；营养数据不完整时如实标注（脚本会自动标注「营养数据不完整」），不假装完整。

## 初次使用 · 三步走（未配置 mcd-mcp 时）

**第 1 步 · 申请 Token（约 1 分钟）**——把这段话原文发给用户：

> 打开麦当劳 MCP 开放平台：**https://open.mcd.cn/mcp/doc**
> ① 点右上角【登录】，手机号验证登录；
> ② 点【控制台】→【激活】申请 MCP Token；
> ③ 同意服务协议后点【一键复制】，把 Token 粘贴到这个对话里发给我。
> ⚠️ Token 等同账号凭证：只发在这条对话里，不要发到群聊或公开场合。

**第 2 步 · 自动配置**（用户贴出 Token 后立即执行，`<skill目录>` 指本 Skill 的 base directory）：

```bash
MCD_MCP_TOKEN='<用户贴的Token>' node "<skill目录>/scripts/setup-connector.mjs"
```

PowerShell：`$env:MCD_MCP_TOKEN='<Token>'; node "<skill目录>/scripts/setup-connector.mjs"; Remove-Item Env:\MCD_MCP_TOKEN`

把脚本输出的验证结果（服务名、工具数、核心工具是否齐全）转述给用户。

**第 3 步 · 激活（按所在平台完成）**：
- WorkBuddy：连接器管理页 → 自定义连接器 → 对 `mcd-mcp` 点「Trust」→ 聊天窗口左下角「+」启用 → 重开一轮会话；
- Claude Code：重启会话（`/mcp` 可确认 `mcd-mcp` 已加载）；
- Codex：重启后运行 `codex mcp list` 确认；
- Trae：按 setup 脚本输出的指引在「设置 → MCP」中添加后重启。

## 第 0 步 · 连接器自检（每次计算前）

先运行体检：

```bash
node "<skill目录>/scripts/check-connector.mjs"
```

| 体检结果 | 处理 |
| --- | --- |
| 「连接器可用」 | 进入主流程 |
| 「未找到 Token」 | 走「初次使用三步走」 |
| Token 有效但核心工具缺失 | 提示用户：先在连接器页 Trust + 左下角「+」启用 + 重开会话；期间可用脚本直连兜底（本 Skill 的脚本不依赖平台工具加载） |
| HTTP 401/403 | Token 失效：引导用户回平台重新申请，重跑 setup-connector.mjs |

若当前环境无法运行脚本，退化为：用工具检索 `calculate-price`、`query-nearby-stores`、`query-meals`，全部检索到即视为可用。

## 主流程

### 1. 需求采集（能默认就默认，减少打扰）

| 维度 | 说明 | 默认 |
| --- | --- | --- |
| 场景 | 到店自取 / 外卖（麦乐送） | 询问（一句问清） |
| 位置 | 到店：城市 + 商圈/地标关键词；外卖：配送地址 | 优先用偏好中的常用位置；「附近」→ 先确认城市（可辅助 IP 定位，需用户同意） |
| 人数 | 1-20 | 1 |
| 想吃什么 | 关键词（「巨无霸」「咖啡」「辣的」…）；想喝饮品/吃冰淇淋也请直接说（默认不计入正餐） | 留空 → 全量正餐候选（人气款优先，仅作参考） |
| 预算 | 总价上限（元） | 不限 |
| 目标模式 | 省钱 / 健康 / 省事 | **每次让用户选**（用户没主意时推荐「省钱」） |
| 购买方式 | 套餐 / 单点 / 都可以 | 都可以（展示时分组，让用户选） |

**需求模糊时：先确认，不猜。** 出现「随便」「都行」「你看着办」「不知道吃什么」或关键信息缺失过多时，用一次轻量确认（AskUserQuestion 或对话），按需问：

- 想吃什么方向？（汉堡类 / 炸鸡类 / 轻食（咖啡、冰淇淋）/ 都可以）
- 预算大概？（不限也行）
- 到店还是外卖？

用户明确说「你决定」时，才直接进入全量推荐（此时把「人气款」作为参考提示之一）。

**用户偏好：首次使用确认，随时可改。** 存储于 `~/.mcd-best-deal/preferences.json`（脚本 `scripts/preferences.mjs`）：

- 首次引导时问 3-4 个问题（别多问）：① 有什么忌口/不爱吃的？② 口味偏好（如爱吃辣）？③ 默认用哪种模式？④ 常用位置（城市 + 商圈）？
- 写入示例：`node scripts/preferences.mjs set --avoid 香菜,洋葱 --prefer 麦辣 --mode save --city 北京 --area 国贸`
- 偏好自动生效：plan.mjs 读取忌口（排除）、口味（优先）、默认模式；collect.mjs 未传位置时使用常用位置。
- 用户说「改偏好」→ 先 `show` 当前偏好，再 `set` 修改。

### 2. 数据采集

```bash
node "<skill目录>/scripts/collect.mjs" --city <城市> --keyword <商圈或地标> --max-stores 2 --output <工作目录>/mcd-data.json
```

外卖场景：`--scene delivery --address-id <地址ID>`。若用户没有配送地址：先问清 城市/联系人/性别/手机号/地址/门牌号，调用 `delivery-create-address` 创建后，用返回的 addressId 采集。

采集内容：候选门店（含距离与营业状态）、每店菜单、每店可用券、券包、营养表——全部实时。

### 3. 方案计算

```bash
node "<skill目录>/scripts/plan.mjs" --input <工作目录>/mcd-data.json --mode <save|healthy|easy> --people <N> [--want <关键词>] [--style any|combo|single] [--budget <数字>] --top 3 --output <工作目录>/mcd-plan.json
```

引擎内部：生成候选（官方套餐 / 单品裸买 / 单点组合 / 券商品方案 / **拆单方案**，多门店并行）→ 逐个调官方算价器 → 按模式权重评分排序。`--style combo|single` 可在用户已明确「只要套餐/只要单点」时收窄候选。

### 4. 结果展示（对话给结论，文件给明细）

必须向用户展示的内容（来自 `mcd-plan.json`）：

- **Top 方案**：每行「方案名 · 门店（距离）· 实付价 · 优惠明细 · 推荐理由」；
- **买法由用户定**（来自 `byStyle`）：把「套餐怎么买」「单点怎么买」「拆单怎么买」分列呈现——
  - 用户没偏好 → 并列给出各组最优（套餐组 / 单点组 / 券组 / 拆单组），标注价格差，让用户挑；
  - 用户说「我就要单点 / 我只要套餐」→ 用 `--style single|combo` 重算（或按 kind 过滤展示），只给对应方式；
- **套餐 vs 单点**：直接转述 `comparisons` 的结论（如「三件套比单点省 ¥12」）；
- **拆单方案**（如有，来自 `byStyle.split`）：逐单列出内容与价格，明确标注「需分 N 次下单、分别支付与取餐」；
- **用券结论（综合评估）**：引擎已对「候选 × 每张可用券」分别试算——同一候选会有「不用券 / 用不同券」的多条结果，展示时突出**用哪张券最划算**，并给出对比基线（不用券实付）；
- **顺便可用券**：`couponHints`（与本次想吃的不相关、但可以直接用的券）；
- **轻食说明**：默认候选不含饮品/冰淇淋/甜点（用户点名时除外）；若用户表达想喝点什么/吃甜品，主动询问是否加入；
- **人气参考**：用户没主意时，可提示候选中的「人气款」（输出字段 `popular`）；
- **计分细则（透明）**：说明本次模式与权重（来自 `rules.json`），并告知「想调整权重/目标 → 说一声即可改」；
- **数据范围与时间**：说明查询了哪些门店、什么时间的价格；
- 有「营养数据不完整」标注时如实转述。

### 5. 确认与下单（可选收尾）

1. 用户选定方案后，如需用「可领取」的券：先 `auto-bind-coupons` 领取，再重跑 `plan.mjs` 确认价格仍成立；
2. 逐项确认：门店、商品、数量、总价、取餐方式（到店：takeWayCode 取算价返回 `takeWayList[].code`；外卖：需 addressId）；
3. `create-order` 创建订单（**不传优惠以外的任何猜测参数**）；
4. 把支付链接原样给用户，由用户自行支付；用户回复支付结果后可用 `query-order` 核实。

## 三种模式与可调规则

模式与权重定义在 `<skill目录>/config/rules.json`——这是全部「取舍细则」的唯一出处，用户可直接编辑：

| 模式 | 目标 | 默认权重（价格/营养/便利） |
| --- | --- | --- |
| save 省钱 | 实付最低（含券、含配送费） | 0.7 / 0.1 / 0.2 |
| healthy 健康 | 满足营养目标区间（热量/蛋白质/脂肪/钠） | 0.2 / 0.6 / 0.2 |
| easy 省事 | 距离最近、步骤最少 | 0.25 / 0.15 / 0.6 |

用户问「为什么这么排」→ 引用权重与对应候选得分解释；用户要调整 → 改 `rules.json`（或按用户口述改）后重跑第 3 步。

## 排障速查（完整手册见 references/troubleshooting.md）

| 现象 | 快速处理 |
| --- | --- |
| 脚本报「未找到 Token」 | 运行 setup-connector.mjs；或设置 `MCD_MCP_TOKEN` |
| HTTP 401/403 / 429 | Token 失效→重新申请；限流→等待约 1 分钟 |
| 试算报「门店暂停营业」 | 换营业中门店；或改用预约单；或换时段 |
| 试算报「暂不支持多张券使用」 | 一单一券：用拆单方案或只保留最优一张 |
| 试算报「促销规则不支持该商品」 | 带券商品必须用券自己的 `products[].productCode` |
| 某门店券列表为空 | 券与门店/时段绑定：换店/时段实时重查 |
| 营养大量「不完整（不计分）」 | 官方两套名称体系所致：如实标注，不硬编数据 |

表中没有的问题、或需要带命令的完整恢复步骤，阅读 `references/troubleshooting.md`。

## 脚本清单（`<skill目录>/scripts/`）

| 脚本 | 职责 |
| --- | --- |
| `check-connector.mjs` | 体检：Token 来源 / 在线验证 / 工具覆盖 |
| `setup-connector.mjs` | 一键配置（多平台）：写通用凭证 + 各平台 MCP 配置（备份+验证+不回显 Token） |
| `collect.mjs` | 数据采集：门店 / 菜单 / 门店券 / 券包 / 营养表 → 归一化 JSON |
| `preferences.mjs` | 用户偏好管理（show / set；存储于 `~/.mcd-best-deal/preferences.json`） |
| `plan.mjs` | 方案引擎：候选枚举（含轻食过滤与偏好）→ 官方试算（含「候选 × 券」综合评估）→ 评分排序 |
| `lib/mcp-client.mjs` | MCP 直连客户端（Streamable HTTP，供以上脚本使用） |

技能根目录另有 `install.sh` / `install.ps1`（一键安装到各平台，详见 `references/platforms.md`）。
